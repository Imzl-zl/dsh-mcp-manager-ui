# 技能管理 + 技能市场

本插件同时有两个能力面：**MCP** 与**技能**。面板顶部的能力层枚举用来切换，两者共享同一个悬浮窗与侧栏入口。

技能能力面解决的是 DSH 自带技能目录**看不到**的那些事：

- 技能到底装在哪个作用域（同名技能跨作用域是合法配置，但模型只会收到生效的那一份）；
- 哪些技能被**停用**了（改名后宿主目录里直接消失，模型和面板都看不见它）——面板会自行扫 `.disabled` 把它们列出来，并给一键恢复；
- 哪些技能**能装、哪些不能装**（许可门禁）。

⚠️ 一个**还没做**的事：宿主对 frontmatter 非法的技能只 `warn` 后跳过，那种技能目前**不会**出现在面板里（要报它得自己扫各根的技能文件并跑一遍校验，见 TODO row 21）。面板不会假装能看到它。

## 打开技能面板

点右下角悬浮按钮或侧栏「MCP」入口打开面板，再点顶部的能力层「**技能**」。

面板分两个模式（第二行左侧的分段控件；两个能力面共用这一条、这个位置、这个控件）：

| 模式 | 用途 |
|---|---|
| **已安装** | 左列表 + 右详情。看本机已有的技能，启停、删除、查看正文与诊断 |
| **发现市场** | 卡片网格。**两个来源**：内置精选（随包、离线、逐技能核过许可，只读目录）与 **skillhub.cn**（外部源、直连上游、只做披露，唯一可安装的来源） |

**作用域药丸只在「已安装」模式出现**，而且与列表分组同源（点哪个药丸，就筛出哪一组，
数字与筛出来的行数一定相等）：市场是目录，装上之后才有作用域，所以安装时才问你装到哪。
MCP 面的市场走的是同一个模式的同一种形态（内联网格，不再是弹窗）。

## 作用域

技能可以装在多个位置，DSH 按优先级依次查找。面板里的作用域候选**来自实际发现的位置**，不是写死的清单——本机就可能没有 `~/.dsh/skills`，技能全在 `~/.agents/skills`。

| 优先级 | 位置 | 说明 |
|---|---|---|
| 100 | `<项目>/.dsh/skills` | 项目级 |
| 200 | `<项目>/.agents/skills` | 项目级 |
| 300 | 自定义目录 | 由宿主配置 |
| 400 | `<DSH_HOME>/skills` | 全局 |
| 500 | `<AGENTS_HOME>/skills` | 全局 |
| 600 | 内置（bundled） | **只读**，不可启停/删除 |

同名技能出现在多个作用域时，面板会标出**哪一份生效、哪一份被遮蔽**——被遮蔽的那份模型收不到，但你确实装了它。

## 启用与停用

DSH 的技能没有「disabled」字段（MCP 有，技能没有），所以启停的做法是把 `SKILL.md` 改名为 `SKILL.md.disabled`：

- 停用后技能从宿主目录里**消失**（宿主按固定路径读 `SKILL.md`，读不到就跳过），
  所以已停用的技能由本面板**自己扫描** `.disabled` 得出，否则你根本看不到它、也没法再启用；
- 内置（bundled）技能只读，不可启停或删除。

## 安装技能

市场里点「安装」会先给你一份披露（安装确认弹窗）：

- **技能正文会作为指令进入模型上下文** —— 这是技能的工作原理，也是它最主要的信任面；
- 是否**含可执行脚本**（`scripts/` 目录）；
- 技能**声明**的工具权限（`allowed-tools`）。注意 DSH 宿主并**不**强制这个字段，
  它只是作者声明的意图——正因如此才要如实披露，让你自己判断。

**只有外部源（skillhub.cn）能一键安装。** 内置精选是**只读目录**：它给你来源、仓库内路径与许可判定，但**不代你下载**——本插件的目录数据里没有记录可固定的 commit，抓默认分支等于每次都装到一个不同的东西，所以宁可不做。点开卡片能看到「来源 / 仓库内路径」，自己取下来之后交给宿主导入即可。

外部源的安装确认弹窗会先把三件事摆出来：

- **技能正文会作为指令进入模型上下文** —— 这是技能的工作原理，也是它最主要的信任面；
- 是否**含可执行脚本**（`scripts/` 目录）；
- 技能**声明**的工具权限（`allowed-tools`）。注意 DSH 宿主并**不**强制这个字段，
  它只是作者声明的意图——正因如此才要如实披露，让你自己判断。

确认后选择装到哪个作用域（全局或某个项目），再执行安装。宿主的导入层支持三种形态：

| 形态 | 装成什么 |
|---|---|
| 单个 `.md` 文件 | 扁平技能 `<name>.md` |
| 技能目录 | 目录捆绑 `<name>/`，连带 `scripts/`、`references/` 等资源 |
| 压缩包 | `.zip` / `.tar` / `.tar.gz` / `.tgz`，按**魔数**识别（下载链接可以不带扩展名） |

⚠️ 这三种形态目前**没有面板入口**（只有宿主 RPC），一键安装走的是外部源的压缩包那条路。要手动导入需要等这个入口做出来——在那之前，面板不会假装它存在。

安装按 frontmatter 里的 `name` 落盘（不是文件名）——宿主就是这么认定技能身份的。
同名技能已存在时会**拒绝而不是覆盖**；压缩包里若有多个技能则拒绝（不替你猜装哪个）。

## 市场的两个来源

「发现市场」里可以切换来源。两个来源的信任模型**不一样**，面板不把它们混成一个：

| 来源 | 是什么 | 信任处理 |
|---|---|---|
| **内置精选** | 随包发布、离线可用；每条都核过来源白名单与许可；**只读目录，不提供一键安装** | **许可门禁是硬闸门**：不可安装的条目仍然显示并说明理由，且没有绕过的入口 |
| **skillhub.cn** | 外部源，直连上游（`api.skillhub.cn`，公开无鉴权）实时搜索与分类；**唯一可一键安装的来源** | **不做许可判定**（上游条目里没有许可信息）：安装前把发布方认证、安全扫描结论、是否需 API Key 摆出来，明确写「本插件未核验」，并要你**勾选确认**后才可安装 |

外部源的请求由**宿主侧**发出——面板本身不联网，所以也不存在浏览器 CORS 问题。它的搜索是**显式触发**的（切来源 / 切分类 / 回车），首屏依旧离线：不联网也能用内置精选。

装 skillhub.cn 的技能时，落点仍由你选（全局或某个项目 × `.dsh` / `.agents`），并且与本地导入走**同一条**写入路径：先下载到临时目录，再按同一套校验解压、挑技能根、拒绝重名。

连接失败只在结果区给一条告警 + 重试，不会让市场页打不开，内置精选不受影响。若你刚更新过面板却看到「外部源不可用」，多半是**宿主进程还是旧的**（它不认识新接口）——重启 DSH 后即可；这种情况下上游一次都没被访问过，所以面板不会把它说成「连接 skillhub.cn 失败」。

## 许可门禁

**内置精选目录**对**每一条技能**单独判定许可，**不按仓库聚合**。这不是保守，是必须的：同一个仓库里既有 Apache-2.0 的技能，也有禁止「在服务之外保留副本」的专有许可技能。

- **不可安装**的条目仍然会显示，并说明理由——你搜 `pdf` 时应该知道「为什么没有」，
  而不是以为面板漏了；
- 未声明许可 = 没有授权 = 不可安装（不会当作「随便用」）；
- 声明与实际冲突时**以技能目录里的许可文件为准**，并在卡片上标出「声明不一致」。

**外部源（skillhub.cn）不适用上面这套**：它的条目里根本没有许可字段，能拿到的只有发布方企业认证与两家安全扫描（腾讯 keen / sanbu）的结论。所以面板**不假装判定许可**，只把这些事实摆出来 + 要你显式确认——你会看到更少的自动判断、更多的原始信息，这是刻意的。

**收录 ≠ 背书。** 技能正文会作为指令进入模型上下文，且可能含可执行脚本。本目录只做来源白名单与许可校验，**不做安全审查**；外部源的条目连许可都无从核实。安装前请确认来源可信。

## 搜索

- **内置精选离线可用**，首屏不依赖网络；
- 内置精选可以叠加 **skills.sh** 的搜索结果作补充：结果按来源白名单过滤——skills.sh 的 `source` 字段**不可信**（实测存在仿冒同名来源），所以只有核实过的来源会显示；
- **skillhub.cn 用自己的搜索与分类接口**（显式触发：切来源 / 切分类 / 回车）。远端结果**不做**许可核实，所以别把远端条目与内置精选里已核过的那些当成一回事；
- 任何一条远端路径失败都静默降级成「仅内置精选」，不会让市场页打不开。
